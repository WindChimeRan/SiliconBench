## Skipped Cells

### hf_transformers — chat + agent — SIGSEGV on MPS
- **Error**: `Segmentation fault: 11` from `serve_hf_transformers.sh:39`
  (`transformers serve --continuous-batching --device mps --dtype bfloat16
  --attn-implementation sdpa`), crashing at `Loading weights: 0%| | 0/473`; run_all
  then reports "Server failed to start within 300 seconds".
- **Not OOM**: `log show` shows no jetsam kill, and this is a 1.6 GB model on a 64 GB
  box.
- **Why skipped**: native crash inside torch/transformers on the MPS backend — root
  cause is in the framework, not the adapter. Workarounds (`--device cpu`, different
  dtype/attn) would change what is being measured and make the cell non-comparable to
  the other frameworks; a clean gap is more honest.
- **Checkpoint-specific**: hf_transformers succeeded on Qwen3-0.6B *and* on
  Gemma-4-E4B-it on this same box.

### sglang — chat + agent — MLX backend lacks hybrid-SSM support
- **Error**: `AttributeError: 'MlxAuxiliaryStateReqToTokenPool' object has no attribute
  'mamba_allocator'` at `scheduler_components/pool_stats_observer.py:249`, reached via
  `event_loop_overlap_mlx -> on_idle() -> get_pool_stats() -> _get_mamba_token_info()`
  (`hardware_backend/mlx/scheduler_mixin.py:276`).
- The `Killed: 9` in the run log is **sglang's own `kill_process_tree`** after its
  scheduler child died — **not** a jetsam OOM (confirmed via `log show`).
- **Diagnosis**: sglang's `is_hybrid_ssm` branch is *correct* for this checkpoint (see
  the config evidence above); the MLX backend simply never implements a
  `mamba_allocator` on its req-to-token pool.
- **Why skipped**: defect is in upstream sglang under `.frameworks/` (off-limits), and
  no serve-level flag bypasses `on_idle()`'s stats path.
- Distinct from the transformers-pin bug fixed in `6dd6027` — that fix **is** working
  here: sglang now reaches scheduler startup instead of dying at import.

### ollama — chat + agent — no Ollama registry tag
- **Error**: HTTP `404 Not Found` on every request (300/300 in each split).
- **Diagnosis**: `models/qwen3.5-0.8b.sh:21` explicitly states *"engines only. No
  OLLAMA_MODEL_NAME set."* `config.sh:43` then derives a fallback tag
  (`qwen3.5-0.8b-bf16`) that is not a real Ollama registry tag, so
  `install_ollama.sh:33` — which pulls only the model active at install time — never
  fetched it.
- **Originally recorded as a 100%-failure result, not a skip.** `serve_ollama.sh` only
  checked that `/v1/models` responds, so the serve was declared healthy and the
  benchmark wrote a result file full of 404s — which reads downstream as a
  catastrophically slow framework rather than an unsupported one.
- **Fixed** in `9916334`: serve now verifies the active model is present in
  `/v1/models` and exits 1 otherwise, so run_all takes its clean-skip path. Verified
  both directions (qwen3-0.6b → exit 0; qwen3.5-0.8b → exit 1 listing available tags).
  The four bogus result files were removed in `9cbd277`.

## Data-integrity correction (`9cbd277`)

`Qwen3.5-0.8B/agent/comparison.json` initially contained an **hf_transformers entry
from a different machine** — timestamp `2026-07-09T02:22:44`, model path
`/Users/haorzhang/applebench/...` (note: `haorzhang`, not `ranzhang`). It reported
success for a cell where hf_transformers actually segfaults on this box.

Cause: the agent sweep was relaunched with `--skip-existing` for all three models
(needed to preserve Qwen3-0.6B's 7 completed cells after the first run was
interrupted). That flag *preserves* old results instead of deleting them at startup,
and the preserved July files ended up with mtimes newer than some of today's — so
`collect_results.py`, which picks the latest per framework **by mtime**, selected one.

12 stale previous-machine files were removed from the two affected agent directories
and every affected `comparison.json` / `REPORT.md` regenerated. All removed files
remain on `origin/main`. Post-fix validation confirms every surviving entry is dated
2026-08-15, carries this machine's paths, and serves the expected model.

**Lesson for future resumes**: `--skip-existing` is per-split and preserves *all* old
results in the directory, including ones from previous machines. When resuming a
partially-completed sweep, scope the resume to the model that was interrupted rather
than applying it to models that have not run yet.
