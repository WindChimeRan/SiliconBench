## Skipped Cells

### mlx_lm (agent)
- **Error**: `silent failure: server returned OK but generated only 0 token(s)` on every `*_vlong_bfcl_v3` prompt (~8835 input tokens), then a hard crash. Server log final line:
  `libc++abi: terminating due to uncaught exception of type std::runtime_error: [METAL] Command buffer execution failed: Insufficient Memory (00000008:kIOGPUCommandBufferCallbackErrorOutOfMemory)`
- **Diagnosis**: The vlong prompts are *fully prompt-processed* (`Prompt processing progress: 8835/8835`), server returns HTTP 200 with **0 generation tokens**, then the Metal command buffer hard-OOMs and the process terminates. New `mlx_lm.server` prompt-cache holds ~10 sequences ≈ 6 GB; with ~8.8K-tok prompts the KV/command-buffer allocation exceeds the Apple Metal budget. This is the **same server-side Metal-OOM class the prior journal documented for mlx_lm agent**, but **regressed worse**: 2026-04-23 (mlx-lm `b7afa33`) was c1 100/0, c8 100/0, c16 16/84; this run (mlx-lm `df1d3f3c`, mlx 0.31.2) is c1 70/30, c8 70/30, c16 10/90 — OOM now bites at c=1.
- **Why skipped, not fixed**: Root cause is mlx/mlx-lm memory behavior upstream (regressed by the version bump), not the adapter. `serve_mlx_lm.sh` has no flag that fixes a generation-side Metal OOM (the prompt processes fine; decode yields nothing). The only candidate knobs (`--prompt-concurrency`, `--prompt-cache-bytes`) are speculative AND would change memory/batching conditions, **invalidating apples-to-apples comparability** with other frameworks and prior weeks while masking a real upstream regression. Editing `benchmark.py` is forbidden. Per skill: a clear skip beats a comparison-breaking over-fix.
- **Why `skipped` not `oom`**: `oom` status is reserved for macOS **jetsam** kills. `log show --predicate 'eventMessage CONTAINS "jetsam"'` for the run window returned **no python/mlx hits**. This is an *in-process* Metal command-buffer OOM exception — exactly how the 2026-04-23 journal classified the same class ("server-side Metal OOM exceptions, not kernel jetsam").
- **Not transient → no retry**: deterministic — the identical 30 vlong prompts fail at c1 and c8; reproduced across all 3 levels. A retry reproduces it.
- **Prior occurrences**: 2026-04-23 agent c=16 (16/84, documented as known/accepted). Same family, worse this week.
- **No cascade**: server crash was isolated to mlx_lm; `run_all.sh` `cleanup()` + fresh serve meant vllm_metal/omlx agent ran clean afterward.
- **Relevant logs**: `.frameworks/mlx_lm_server.log` (line 1955 = the OOM crash); `results/Qwen3-0.6B/weekly_2026-05-19.log` (grep `mlx_lm` agent block); `results/Qwen3-0.6B/agent/mlx_lm_20260519_015543.json` (degraded result).
